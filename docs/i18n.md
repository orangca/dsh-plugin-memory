# 模型可见文本多语言（language）—— M11

> 竞品对照的第三个方向。`dsh-memento` 有 `language: 'en' | 'zh'` 配置，覆盖**模型可见文本与命令输出**，
> 而我们的注入块、页脚、提示词、工具描述**全是中文写死** —— 对英文用户是硬伤：模型每回合看到的
> 都是中文指令。本文是并行实现的接口契约（签名冻结）。

## 1. 范围（本轮**只做模型可见文本**）

| 类别 | 是否本轮本地化 | 说明 |
|---|---|---|
| 注入块头/页脚（常驻记忆、项目印象、人格、工作约定、自我观察） | ✅ 是 | 每一轮都进上下文，影响最大 |
| 注入提示词（`REFLECT_NOTICE`、`INTRO_NOTICE`） | ✅ 是 | 同上 |
| 每轮召回块头/页脚（R2，目前在 `index.ts` 内联） | ✅ 是 | 同上 |
| 7 个 `memory_*` 工具的**描述与参数说明** | ✅ 是 | 工具 schema 直接进模型上下文 |
| 命令输出（`/memory list`、`/sleep` 预览、stats…） | ❌ 本轮不做 | 用户可见、量大；**在 README 里明确写清"命令输出仍为中文"**，留作后续 |

**硬要求**：默认 `'zh'` 必须与 0.5.10 **逐字节等价**（升级后行为不变）。

## 2. 配置

| 键 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `language` | `'zh' \| 'en'` | `'zh'` | **模型可见文本**的语言（不含命令输出） |

## 3. `src/lib.ts` 的新增导出（签名冻结）

```ts
export type Language = 'zh' | 'en'

/** 容错解析：非法/缺失 → 'zh'（默认语言必须保持现状）。 */
export function normalizeLanguage(value: unknown): Language

/** 一套完整文案（所有模型可见文本）。 */
export interface InjectedTexts {
  factsHeader: string
  factsFooter: string
  gistHeader: string
  gistFooter: string
  personaHeader: string
  personaFooter: string
  workConfirmedHeader: string
  workObservedHeader: string
  workObservedFooter: string
  recallHeader: string
  recallFooter: string
  reflectNotice: string
  introNotice: string
  /** 自画像为空/待确认队列为空这类「无内容」提示（注入与命令共用同一套语气）。 */
  emptySelfPortrait: string
  emptyPendingQueue: string
}

/** 取某语言的文案表（缺省 'zh'）。返回值必须是**冻结的常量表**，不要每次新建对象。 */
export function localizedTexts(language?: unknown): InjectedTexts

/** 便利：`localizedTexts(cfg.language)`。 */
export function textsFor(cfg: MemoryConfig): InjectedTexts
```

**既有导出的中文常量一律保留**（`PERSONA_HEADER`/`PERSONA_FOOTER`/`WORK_*`/`REFLECT_NOTICE`/`INTRO_NOTICE`），
它们继续是 zh 文案 —— 既有测试与调用方不受影响；新代码走 `textsFor(cfg)`。

### 3.1 语言表的要求

- **zh 表必须与现有常量逐字一致**（有测试直接比对，例如 `textsFor({...DEFAULTS}).personaFooter === PERSONA_FOOTER`）。
- **en 表**：
  - 语义必须与 zh 一一对应（尤其：人格页脚那句「描述而非指令、以事实为准、先看合理性与可行性、不为迎合而附和」，
    工作页脚「判断依据是事实与实际效果，而不是谁说得更肯定」，反思提示的四条硬要求，初次设定的四条硬要求）。
  - **不得出现任何 CJK 字符**（测试用 `/[\u4e00-\u9fff]/u` 断言），避免半中半英。
  - 所有单行提示（`reflectNotice`/`introNotice`）必须**单行**（不允许 `\n`）且长度不得超过 zh 的 1.6 倍
    （英文按字符算更长，给它一点余量，但不能失控）。
- 两个语言的块头都用 `[...]` 包裹，保持既有视觉结构。

### 3.2 英文块级开销与预算余量（0.5.12 补，实测逼出来的）

`charsPerToken` 默认 **2.5** 是中文/英文的保守折中，而英文真实约 4 字/token ⇒ 同一意思的英文块级固定文案
要花约 **2.5 倍**预算。实测（token）：

| 块 | zh 固定开销 | en 固定开销 | 默认预算 | 英文剩余 |
|---|---|---|---|---|
| 人格（块头+页脚） | 31 | **67** | `selfPersonaMaxTokens` 80 | 13 ⇒ **一条普通英文记忆都放不下，整节静默为空** |
| 工作三块 | 31 | **79** | `selfPortraitMaxTokens` 120 | 41（勉强） |
| 常驻 facts + 印象 | 46 | **167** | `maxInjectedTokens` 300 | 133 |

修法：给英文一份**显式余量** `EN_BLOCK_HEADROOM = 48`，只在 `language === 'en'` 时加到
`selfPersonaMaxTokens` / `selfPortraitMaxTokens` 上（zh 逐字节不变）。
**不动 `maxInjectedTokens`** —— 那是用户自己设的硬上限，不该被语言悄悄放大；英文用户如觉得常驻块装得少，
自行调大即可（README 已说明）。
测试钉死：英文默认预算下人格与工作两节都必须渲染出内容，且内容空间 ≥ 25 / ≥ 40 token。

## 4. `src/index.ts` 的宿主行为

1. **注入路径全部改用 `textsFor(cfg)`**：
   - 常驻块：`renderContextBlock`/`renderSelfBlock`（lib 内部改，见 §3）；
   - R2：`R2_HEADER`/`R2_FOOTER` 从内联字面量改为 `textsFor(cfg).recallHeader/recallFooter`（**保持既有的预算计算口径**：
     块头尾仍先扣预算）；
   - 反思提示：`REFLECT_NOTICE` → `textsFor(cfg).reflectNotice`；初次设定：`INTRO_NOTICE` → `textsFor(cfg).introNotice`；
   - 注入正文照旧过 `clampText`（单行）与 `maxInjectedTokens` 预算。
2. **7 个工具的描述与参数说明**按 `cfg.language` 取文案：把描述集中成一个 `toolTexts(language)` 表（放在 index.ts 或 lib），
   中英各一套；`name`/参数名/schema 结构**一律不变**（工具契约不能因为语言而变）。
3. **命令输出保持中文**（本轮范围外），但 `/memory stats` 增加一行显示当前 `language` 值（便于排查"为什么模型看到中文"）。
4. `Schema` 增加 `language`（`union(['zh','en'])`，默认 `'zh'`），**volatile**（要与设置页字段对应）。

## 5. 不可妥协项

- **默认 `'zh'` 与 0.5.10 逐字节等价**：`language` 缺失/非法/未设置时，注入的每一个字节都与现在相同。
- **工具契约不随语言变**：工具名、参数名、必填项、schema 结构不得因 `language` 改变（否则会破坏模型已学的调用方式）。
- **不夹带**：en 表不得含 CJK 字符；zh 表不得因为改动而漏字（有逐字比对测试）。
- **预算口径不变**：`language` 切换不得改变 token 预算算法（英文更长会自然占更多预算，这是预期行为，但不许改算法）。

  `/memory stats` 显示语言；`language` 非法值回落 zh。
