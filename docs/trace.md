# 来源反查（`/memory trace`）—— M15-A

> M9 让每条记忆有了出处（`refs` = 会话 + 事件序号区间），M13 让**用户**能核对单条（`/memory verify <id>`）。
> 缺的是**反向**那条路：从一次会话（或某个事件序号）出发，看它留下了哪些记忆。
> 典型用途：「昨天那次对话到底沉淀了什么」「这条 10329 号事件写过什么记忆」。
> 本文是接口契约（签名冻结）。

## 1. 范围与形态：**只加命令，不加工具**

- 新命令：`/memory trace <sessionId 前缀> [#<seq>]`
  - `<sessionId 前缀>`：会话 id 的前缀（完整 id 是 `session-84a547da-…` 这种形态；前缀唯一即可，歧义要报错并列出候选）。
  - `#<seq>`（可选）：只看**区间覆盖该序号**的引用（`from <= seq && (to ?? from) >= seq`）。
  - 也接受 `--at <seq>` 等价写法。
- **不新增第 8 个工具**：现有测试与 README 都钉着「7 个工具」，且 M11 契约测试逐字钉着工具描述与参数说明。
  模型侧本来就能读到 `refs` 字段并用 `/memory verify` 核对，反查主要是**人**的入口。
  （工具级 `sessionId` 过滤留作后续独立一轮。）

## 2. 行为

```
/memory trace 84a547da            → 列出所有引用指向该会话的记录
/memory trace 84a547da #10329     → 只列区间覆盖 10329 的记录
/memory trace session-84a547da-5727-4ffc-adf0-26d02e749e13   → 完整 id 也可以
```

输出（命令输出，**中文**，与其它命令一致）：

1. 首行：`[来源反查 · 会话 <匹配到的完整 id 或前缀>#<seq 或 ->>]`
2. 命中条数：`命中 N 条（库内共 M 条记录）`；0 条时给可读说明（「没有任何记忆引用这个会话」/「这个会话有 K 条记忆，但都不覆盖 #seq」两种要分开说）。
3. 每条一行：`- <id 前缀> · <kind[/facet]> · <status> · <origin> · <refs> · <正文预览（过 clampText，单行）>`
   —— 行内必须能看到**具体是哪个区间**命中（若带 `#seq`，把命中的那条引用标出来）。
4. 末尾一行提示：`用 /memory show <id> 看全文，/memory verify <id> 回到原文核对。`

## 3. 实现约束

- **纯读取**：不写记录、不改状态、不推审计事件、不 markUsed（反查不是"使用"）。
- 只在**既有 helper** 上实现（`refsOf` / `refsToString` / `formatRefs` / `clampText`）；**不要改 `src/lib.ts`**
  （另一个代理正在改它的检索评分）。
- 分支过滤照常生效（`branchVisible`）：被分支挡下的记录不出现在反查结果里；
  但 `memory_explain` 那种"诊断可见"不适用于本命令的默认输出 —— **默认要过滤**，保持一致。
- pending 记录（`status: 'pending'`）**不进**本命令输出（与其它列表一致；M10 契约 §4.3）。
- 会话 id 前缀歧义 / 找不到 / 参数非法：都要明确报错，不抛异常。
- 命令用法要进 `/memory help` 与命令的 `input.hint`。

## 4. 验收标准

- `pnpm typecheck` 四套全绿；`pnpm test` 全绿（现有 **273** 项不许回退）。
- host 测试至少覆盖：命中一条、命中多条并按时间/确定性顺序、`#seq` 过滤（覆盖 / 不覆盖两种）、
  前缀歧义报错、找不到报错、0 命中的两种文案、**不写盘不改状态**（deepEqual 快照）、
  被分支挡下的记录不出现、pending 不出现、help 文案包含 trace。
- 文档：两份 README 的命令清单各加一行（**必须中英对齐**，`pnpm check:readmes` 会验）；
  `CHANGELOG.md` 由 Lead 在集成时统一写。
